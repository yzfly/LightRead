# LightRead 论文阅读完整指南

LightRead 的论文阅读不是一个独立的 AI 按钮，而是一条从清晰阅读、定位批注、翻译，到本机 Agent 深读和人工形成结论的完整工作流。

> v1.1.10 提供本机论文 Agent 与人工修订论文十问。v1.1.9 已包含无接缝连续阅读；v1.1.8 和 v1.1.7 分别包含 PDF 贴合渲染、论文翻译与快捷键增强。

## 1. 阅读与定位

| 能力 | 说明 |
|---|---|
| 渲染引擎 | MuPDF / PDFium 可选，默认 MuPDF；PDFium 同时提供文本几何、搜索、链接和批注能力 |
| 默认模式 | 连续滚动、适宽显示，页面四周与页间没有额外接缝 |
| 页面模式 | 连续滚动、单页、对页、书籍视图；可切换适宽、适高和固定缩放比例 |
| 导航 | 缩略图、目录、页码、PDF 内部链接、跳转后返回 |
| 搜索 | `Ctrl/Cmd + F` 搜索文本并在结果之间跳转 |
| 批注 | 选择文字后高亮、写想法；可在批注列表定位或删除 |
| 辅助阅读 | 自动滚动 / 翻页、全屏、幻灯片、带文本层 PDF 的逐页朗读 |

LightRead 始终保留原始 PDF 版式，不把论文重排成容易破坏公式、图表和双栏关系的单栏正文。适宽、适高和百分比缩放使用一致的 96 DPI 语义，并按照设备像素绘制页面。

## 2. 翻译

翻译与本机 Agent 是两条独立路径，未安装 Agent 不影响翻译。

- **划词翻译**：选中文字后从浮动工具条发起。
- **逐页翻译**：右侧栏提供版式对照和段落列表，只翻译滚动到的页面并缓存结果。
- **BabelDOC 整本翻译**：桌面端生成保持公式、图表和布局的中文或双语 PDF，并自动导入论文库。
- **术语上下文**：BabelDOC 可以使用经用户确认的论文主题与术语上下文，减少同一术语前后不一致。

划词与逐页翻译使用“设置 → AI 助手”中配置的 OpenAI 兼容服务。BabelDOC 有独立安装的本地运行环境，但翻译模型仍使用这里配置的个人 Base URL、API Key 和模型；它不能使用 LightRead 的内置试用通道。打开论文本身不会自动发起模型请求。

## 3. 本机论文 Agent

### 最简单的选择：只安装 Pi

Pi Agent 是 LightRead 的默认引擎和主路径。Codex、Claude Code 都不是必需项：

1. 按 [Pi 官方说明](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/README.md) 安装 Pi 0.78 或更高版本，并在 Pi 中完成模型提供商配置。
2. 打开“设置 → 论文 Agent”，确认 Pi 的版本和可用状态。
3. 如果桌面应用没有从图形界面的 PATH 找到 `pi`，手动选择其可执行文件。
4. 打开论文右侧的 **Agent**，直接提问或进入 **论文十问**。

不使用 Agent 时无需安装任何 CLI。LightRead 不会替你安装、登录或保存引擎凭据。

### 引擎差异

| 引擎 | 定位 | 是否必需 | 会话协议与认证 |
|---|---|---|---|
| **Pi Agent** | 默认推荐 | 否；但它是启用 Agent 的最短路径 | 使用 Pi RPC 和 Pi 自己的提供商、模型、工具、扩展与登录配置 |
| Codex | 可选增强 | 否 | 使用 Codex app-server 和 Codex 自己的登录、审批及工具配置 |
| Claude Code | 可选增强 | 否 | 使用 Claude Code 流式协议；仅接入 API Key 或支持的企业 / 云提供商认证，不接入个人 `claude.ai` OAuth |

任一引擎缺失、版本不兼容或未登录，只会禁用该引擎，不会阻塞 Pi、其他引擎、论文翻译或普通阅读。三个引擎的会话相互独立，但同一篇论文共享一个可写工作区。

### Agent 自动读取什么

发送问题前，LightRead 会从当前 PDF 和批注数据库生成一份版本化快照：

```text
paper-agents/<paper-id>/
├── current-paper/
│   ├── paper.pdf       原论文的只读副本，不是链接
│   ├── paper.txt       带稳定页码标记的完整文本，不按字符截断
│   ├── notes.md        全部高亮与笔记
│   └── context.md      标题、页数、当前页、选中文本、提取状态与哈希
├── workspace/          Agent 可写，三个引擎共享
└── conversations/      各引擎独立的事件与原生会话信息
```

`paper.txt` 会逐页提取全文。没有文本层的页面会保留明确标记；扫描版论文仍可由 Agent 打开 `paper.pdf`，但 LightRead 不承诺所有引擎都具备视觉理解能力。

`notes.md` 包含批注 ID、页码、选中文字、用户笔记、颜色和时间。`context.md` 会在下一次发送前更新当前页和选中文本，不包含屏幕坐标或引擎凭据。

四个 `current-paper` 文件默认标记为只读，并在哈希变化时由原始 PDF 与批注重新生成。它们用于防止误写，不是限制同一系统用户的安全沙箱。Agent 保留安装时已有的联网、终端、工具、扩展与子 Agent 能力，正常写入位置是 `workspace/`。

### 对话、权限与停止

- 输出会流式显示，同时展示精简的工具活动。
- 引擎请求权限或补充输入时，LightRead 显示原生选项，不会自动批准。
- 同一篇论文一次只运行一个 Agent 回合；切换引擎仍可查看历史，但需要等待当前回合结束或点击 **停止**。
- 收起侧栏或离开论文不会自动停止回合；显式停止和应用退出会终止受管理的进程树。
- 对话事件先写入磁盘再投射到界面。异常退出后保留已生成文本和工作区文件，不会自动重发上一条用户消息。

## 4. 论文十问：AI 与人工答案分开

每个问题都维护三个不同字段：

1. **AI 初答**：只读，一旦完成不会被后续编辑覆盖。
2. **我的回答**：初次可由 AI 初答填充为草稿，之后完全由用户编辑和保存。
3. **AI 再答**：用户点击“保存并让 AI 再答”后，Agent 读取固定问题、AI 初答、准确的人工版本和最新论文上下文，再给出独立回答。

输入、自动保存、失去焦点或切换引擎都不会自动调用 Agent。AI 再答与提交时的人工修订版本绑定；如果用户继续编辑，旧结果仍会保留，但会标记为过期，绝不会覆盖新的人工答案。

## 5. 数据、备份与删除

- 原始 PDF、书目和批注仍由 LightRead 书库管理；Agent 只读取重新生成的副本。
- Agent 数据位于系统应用数据目录，不跟随自定义书库位置迁移。
- 对话、工作区和论文十问人工答案目前不进入 OKF 或 WebDAV 备份。
- 对话事件与工具活动可能包含用户问题、论文摘录和 Agent 输出；分享日志或工作区文件前应先移除私密内容。
- 删除 PDF 前，LightRead 会先停止该论文的活动 Agent，再清理快照、会话、工作区和论文十问数据；清理失败会中止删除，避免留下半删除状态。
- Web 与移动端不显示本机 Agent，但 PDF 阅读和既有翻译能力继续可用。

## 6. 常见排错

### Pi 显示“未找到”

桌面应用从 Finder、开始菜单或桌面环境启动时，PATH 可能不同于终端。进入“设置 → 论文 Agent”，为 Pi 选择绝对可执行文件路径。可以先在终端运行 `pi --version`，确认版本不低于 0.78。

### Agent 读不到某一页

先确认 PDF 是否带文本层。扫描页会在 `paper.txt` 中显示为空页或无文本标记；这不是截断。可以要求 Agent 打开 `paper.pdf` 检查页面，但结果取决于当前模型和工具是否支持视觉 PDF。

### 笔记没有出现在回答里

保存笔记后再发送下一条问题。正在运行的回合固定使用启动时的上下文版本；新的页码、选择和笔记只应用到下一回合。

### Claude Code 为什么不可用

LightRead 会阻止个人 Claude 订阅 OAuth 经第三方集成发起模型请求。需要使用 Claude Code 支持的 API Key、企业或云提供商认证；也可以直接使用默认的 Pi 路径。
